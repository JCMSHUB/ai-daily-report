# AI 个人情报简报 — 发现与检索框架

Version: 4.3

## 目标

检索的单位是“可改变判断的事件”，不是新闻标题、公司动态或网页数量。一个候选必须最终能回答：发生了什么实质变化、证据是什么、它让读者现在做出什么不同选择。

优先发现：

- 能改变工具选择、部署方式、学习顺序或风险判断的变化。
- 有实际入口、可在有限时间内验证价值的工具、模型、repo、API、论文或数据。
- 会影响后续观察对象的价格、能力、权限、基础设施或监管变化。

不把融资、观点、流量争议或常规版本宣传误写为事件增量。

## 时间与来源原则

- 日报默认窗口为最近约 24 小时，周报使用本周统计窗口。候选的原始发布时间或实质更新时间必须落在对应窗口内。
- 搜索结果的收录时间、媒体转述时间和页面更新时间不能替代事件时间。
- 必须区分 `announced`、`preview`、`available`、`weights released` 与 `GA`。较新的报道不能把计划或预告自动升级为已经可用。
- 原始材料优先级：官方公告 / API 文档 / release note / GitHub / Hugging Face / arXiv / 监管文件。
- Reuters、Bloomberg、FT、The Information、SemiAnalysis 等用于发现线索、补足商业事实或交叉验证；不能把媒体首页、搜索页、作者页或主题页作为证据。
- 低优先级站点只可提供线索，必须回溯到原始材料或独立高质量报道。

## 五层初始扫描

每层只执行 1 条综合查询，共 5 条。查询不是关键词堆砌，而是由以下三部分组成：

```text
[主题实体或技术锚点] + [实质事件词] + [窗口与证据意图]
```

实质事件词优先使用：`release`、`release notes`、`API`、`pricing`、`availability`、`benchmark`、`model card`、`security`、`policy`、`rule`、`documentation`。避免只搜 `news`、`update`、`AI` 这类宽词。

| 主题层 | 事件锚点 | 优先证据 |
| --- | --- | --- |
| Frontier Models | 模型发布、API/价格、模型卡、能力限制 | 官方发布、API 文档、模型卡、benchmark |
| Agent Runtime | Codex、Claude Code、MCP、浏览器/计算机使用、权限、长期任务 | release、docs、GitHub、安全说明 |
| Inference Infrastructure | vLLM、CUDA、GPU、推理服务、成本、供给约束 | release、性能材料、价格页、官方/高质量商业报道 |
| Open Source Ecosystem | 开源模型、repo、框架、本地推理、可复现实验 | GitHub、Hugging Face、论文、模型卡 |
| Governance & Regulation | 监管、版权、出口管制、安全/合规框架 | 监管文件、法院/政府文件、官方公告 |

主题内实体应随近期生态变化轮换，但保持个人优先级。例：对 Agent Runtime，不是搜索“agent news”，而是搜索有明确实体的“`MCP agent runtime release notes security last day`”。

## 调用预算与执行

- 初始扫描：`search_depth: basic`，当前实例支持时可用 `fast`；`time_range: day`；`max_results: 6~8`；`include_raw_content: false`。
- 同批查询并发，建议并发度不超过 3；运行时不支持并发时保持相同预算。
- 每层返回后立即抽取候选事件、原始 URL、发布时间和可能的决策影响。不要在 Discovery 阶段写新闻摘要。
- 某层没有通过硬门槛的候选时，才可增加 1 条 `advanced` 查询；该查询必须写明实体、缺失证据或事件类型，例如“某 API 价格变更的官方价格页”，不能泛搜补数量。
- `可以忽略` 只来自初始扫描中确实占据信息流的高热度低增量话题。没有这种话题时省略该栏目，不额外检索噪音。

## 候选卡与停止条件

Discovery 后先以一行一事件形成候选卡：

| 字段 | 要求 |
| --- | --- |
| 事件键 | 用 `实体 + 对象 + 动作/版本` 标识底层事件，转载或换标题不产生新事件键 |
| 事件与时间 | 实体、动作、对象、结果，以及一手来源中的原始发布时间/实质更新时间 |
| 状态变化 | 前一状态、当前状态及证据；不得混淆预告、预览、可用、权重发布和 GA |
| 实质增量 | 相对一手来源时间线，以及日报最新最多 3 期 / 周报本周最多 7 期简报，新了什么；没有增量即剔除 |
| 决策影响 | 工具、学习、部署、风险或观察对象会怎样变化 |
| 主要证据 | 具体 URL、来源等级与证据类型；技术和治理事件必须使用可获得的一手材料 |
| 缺口 | 需 extract 或交叉验证的具体主张 |
| 处理 | 入围 Verification / 剔除、唯一主栏目，以及原因 |

按底层事件聚类。一个官方发布加十篇转述仍是一件事；多个公司在同日发布相似内容，只有它们共同支持同一判断时才是独立信号。

近期简报目录默认为 `~/.openclaw/ai-daily-report/recent-reports`，可由 `AI_DAILY_REPORT_LOCAL_DIR` 覆盖。Discovery 形成候选后，日报按修改时间取最新最多 3 个 Markdown，周报取本周最新最多 7 个；只搜索候选的实体、对象、版本和事件键，再读取命中段落，不得把所有旧简报整篇加载到上下文。

近期简报只作为事件对照数据，不能代替本次 Discovery、来源时间核对或 Verification。目录不存在或没有简报时，在候选卡中记录“无本地近期简报”，并以一手来源时间线建立前一状态；不得假装已经完成跨期对照。

疑似旧闻只做一次定向日期核查：用明确实体和版本搜索或提取一手来源中的发布日期/实质更新时间。若仍不能证明窗口内增量，立即剔除，不继续排除性追查。搜索 snippet 只可用于明确剔除旧闻或定位一手 URL，不得支撑入选主张。

五层扫描和候选硬门槛检查后，若没有候选通过四个硬门槛，立即判定为低信号期并停止检索；不进入 Verification Search，也不执行无实体锚点的泛化追查。当已有合格候选，或后续查询不再产出新的合格事件或必要证据时同样停止。目标总调用量通常为 7~9 次，但事实门槛高于预算，且预算绝不是填满配额的理由。

## Verification 路由

对入围候选逐个执行当前实例带前缀的 `__tavily_extract`，每次只传 1 个原始 URL，并用 query 聚焦待验证主张。同一 URL 提取失败后不重试；可定向搜索另一份一手材料，但 snippet 只能用于路由或剔除。只为明确证据缺口搜索：

- 原始来源不存在或不完整。
- 商业事实缺少第二个独立高质量来源。
- 数字、benchmark、能力范围、监管命令或生效日期不明确。
- 趋势判断缺少第二个已经入围的独立底层事件。

Verification Search 使用 `search_depth: advanced`、`max_results: 3~5`，按底层事件合并，通常为 1~3 次。对每个最终候选建立原子事实证据记录：

| 字段 | 要求 |
| --- | --- |
| 原子事实 | 一行只写一个将进入正文、可独立判真的核心主张 |
| 发布状态与事件时间 | 使用一手材料中的准确状态和时间 |
| 证据 | 具体 URL，以及能直接支持该事实的原文或准确释义 |
| 来源等级 | 按 `event-quality.md` 标 A/B/C/D |
| 结果 | 通过 / 矛盾 / 缺证；后两者不得写入正文 |

不能用“链接与事件相关”代替逐项支持。任何最终会写入的事实必须能在对应记录中找到依据。

## 成功标准

- 候选池覆盖多个主题层是偏好，不是配额；当天高质量信号集中在一个方向时允许集中输出。
- 最终只保留能通过 `event-quality.md` 硬门槛和验证要求的项目。
- 没有合格 `值得尝试`、`可以忽略` 或趋势信号时，省略相应栏目。
- 不使用低质量内容填充主题、栏目、字数或调用预算。
