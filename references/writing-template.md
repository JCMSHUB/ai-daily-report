# AI 情报简报写作模板

## 标题

```markdown
# AI 情报简报 — YYYY-MM-DD
```

## 写作原则

简报是注意力分配工具，不是新闻汇总。每项内容按“事实 -> 判断 -> 行动/观察”组织：事实可追溯，判断明确标为判断，行动能在有限时间内完成或验证。

- 只保留已通过事件筛选和 Verification 的项目。
- 每个底层事件只选择一个正文主栏目；其他章节可以引用，不重复叙述同一事实。
- 不因栏目、主题覆盖、推荐长度或历史格式而补内容。
- 标准 Markdown；不使用 HTML、内联样式、引用块或复杂嵌套。
- 单个 bullet 不超过 180 个中文字符；超过则拆分。
- 篇幅由合格事件决定，最高 8000 个中文字符；没有最小长度。
- 信源标签与真实来源一致。技术与治理事件引用可获得的一手材料；商业或高风险主张列出主证据与交叉证据。
- 发布状态沿用验证记录中的准确措辞；不得把预告、预览、可用、权重发布或 GA 改写成更强状态。

## 🧭 今日结论

只写 1-3 条最重要、可被后续验证的判断。没有足够强的判断时允许更少。每条都必须对应正文的已验证事件或独立趋势信号，不能只是新闻标题。低信号期只写 1 条结论，说明扫描窗口、覆盖范围和没有候选通过硬门槛，然后直接写时间底注；这不是事件事实，其余栏目全部省略。

```markdown
- [判断]：这改变了什么判断或优先级；其依据见下文 [事件名称]。
```

## 🔎 值得跟踪

仅放需要后续关注的事件。通常不超过 4 条，质量不足时更少。

```markdown
### N. [事件标题] 🕐/🗓️/⏪

- 事实：[实体 + 动作 + 对象 + 结果；不加入未经证实的推断。]
- 判断：[为什么这会影响工具、部署、学习、风险或产业观察。]
- 下次检查：[具体 release、文档、价格页、benchmark、监管文件或财报。]
- 时间：[明天 / 1 周内 / 1 个月内 / 季度内。]
- 信源：[主证据：具体页面](URL)；[交叉证据：具体页面](URL)（仅在需要时）。
```

## 🧪 值得尝试

只列能亲自验证价值的对象。没有合格对象则省略。

```markdown
### N. [名称]

- 场景：[要解决的具体问题。]
- 为什么现在试：[本次事件带来的新能力、入口或信息增量。]
- 最小验证：[在限定时间内完成什么，以什么结果判断是否值得继续。]
- 成本：[低/中/高；依赖、账号、硬件或时间。]
- 入口：[GitHub / Demo / Docs / Paper / API](URL)
```

## 🧹 可以忽略

只解释当天确实占据信息流但不应分散注意力的话题。没有此类话题则省略。

```markdown
- [事件/话题]：忽略原因必须具体，例如无原始证据、无技术增量、只是重复叙事，或不会改变任何近期决策。
```

## 📈 趋势判断

只有至少两个不同且已经在正文出现、通过 Verification 的底层事件时才保留本节。第二个来源只是验证材料，不是第二个趋势信号；不要在本节引入新事件、新数字或未验证事实。

```markdown
### [趋势命题]

[150-350 字：说明趋势、它对读者的含义，以及不确定性。]

- 支持事件：[正文事件 A] / [正文事件 B]
- 反证条件：[什么发生时该判断不成立]
- 观察指标：[后续具体指标或渠道]
```

## ✅ 我的行动清单

最多 3 条，只能从正文已验证事实推出。每条都必须有对象、目的、完成条件和时间。

```markdown
- 阅读：[具体文章/论文/文档]；目的：[要澄清的判断]；完成：[读完后记录一个结论]；时间：[何时完成]。
- 试用：[具体工具/模型/repo]；目标：[验证什么]；完成：[可复现一个结果或明确放弃原因]；时间：[何时完成]。
- 跟踪：[具体事件/渠道]；检查：[何种变化]；时间：[何时复查]。
```

## 📌 时间标记与底注

- 🕐：24 小时内首次发布或发生实质更新。
- 🗓️：有明确时间线的持续事件。
- ⏪：非当日首发，但本窗口内出现重要且可验证的新材料；正文必须说明新增内容。

```markdown
_📅 数据截至 YYYY-MM-DD HH:MM CST | 💡 本简报仅保留可验证且能影响注意力分配的信号。_
```

周报标题为 `# AI 情报周报 — YYYY-Www`，将“今日结论”改为“本周结论”，“我的行动清单”改为“下周行动清单”，其余证据与行动要求不变。
