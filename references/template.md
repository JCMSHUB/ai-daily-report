# AI 情报简报写作模板

## 标题格式

```markdown
# AI 情报简报 — YYYY-MM-DD
```

## 写作目标

本简报不是新闻汇总，而是个人注意力分配工具。输出必须帮助读者判断：

- 哪些变化值得持续跟踪。
- 哪些工具、论文、模型、框架值得亲自试用。
- 哪些热闹事件可以忽略。
- 今天的信息能转化成什么行动。

## Markdown 排版规范

- 使用标准 Markdown，不使用 HTML、内联样式、字体标签或手工字号控制。
- 最终正文不要使用 `>` 引用块。
- 同一段落内只使用一种正文层级。
- 单个 bullet 控制在 180 个中文字符以内；超过则拆成多个同级 bullet。
- 信源、试用入口、观察渠道统一使用普通无序列表。
- 推荐 2500-6000 个中文字符，最高不超过 8000；低于推荐范围不视为失败。
- 禁止为满足字数扩写、重复表达、加入空泛分析，或将数字改写成中文大写/口语表达来凑字数。
- 信源标签必须与链接来源一致；第三方分析不能标为官方公告，作者页/主题页/首页不能标为原始信源。

## 🧭 今日结论

输出 3-5 条直接判断，不复述新闻标题。每条必须是可被后续验证的判断。

```markdown
- [判断]：一句话说明今天最重要的变化，以及它对技术判断、工具选择、学习重点或产业观察的影响。
```

---

## 🔎 值得跟踪

只保留需要后续关注的事件，通常 2-4 条。每条说明观察价值，不做新闻堆砌。

```markdown
### N. [事件标题] 🕐/🗓️/⏪

- 发生了什么：[明确实体 + 动作 + 对象 + 结果。]
- 为什么值得跟踪：[说明它影响谁、改变什么、可能指向什么趋势。]
- 观察窗口：[明天 / 1 周内 / 1 个月内 / 季度内。]
- 下次检查：[具体检查对象，例如 GitHub release、API 文档、监管文件、价格页、benchmark、财报电话会。]
- 信源：[具体文章/论文/仓库/公告](URL)
```

---

## 🧪 值得尝试

只列值得亲自试用或阅读的工具、模型、框架、论文、repo、产品，通常 1-4 条。没有合格对象时可省略本节。

```markdown
### N. [名称]

- 适合场景：[它适合解决什么具体问题。]
- 试用理由：[为什么现在值得试，而不是以后再看。]
- 试用成本：[低/中/高；说明依赖、API、硬件、账号、时间成本。]
- 入口：[GitHub / Demo / Docs / Paper / API](URL)
```

---

## 🧹 可以忽略

通常列 2-4 条当天热闹但不值得投入注意力的信息，并解释忽略理由。若没有明显占据信息流且值得专门解释的噪音，可以省略本节；不得为保留栏目追加低价值搜索或硬凑内容。

```markdown
- [事件/话题]：忽略原因，例如缺少一手信源、只有 PR 叙事、无技术增量、与个人工具选择无关、短期不可行动。
```

---

## 📈 趋势判断

用 300-600 字总结一个真正有判断价值的方向。不要复述前文，必须形成一个可跟踪判断。

可选结构：

```markdown
### [趋势命题]

[判断正文。说明触发信号、支持事件、反证条件和后续观察指标。]

- 支持信号：[事件 A] / [事件 B]
- 反证条件：[什么发生时说明该判断不成立]
- 观察指标：[具体指标或渠道]
```

---

## ✅ 我的行动清单

最多 3 条，只写可执行动作。

```markdown
- 阅读：[具体文章/论文/文档]，目的：[为什么读]
- 试用：[具体工具/模型/repo]，目标：[验证什么]
- 跟踪：[具体事件/渠道]，时间：[什么时候再看]
```

---

## 📌 时间戳规范

- 🕐 = 24 小时内首发或发生突破的事件
- 🗓️ = 有明确时间线的事件（多日持续演进）
- ⏪ = 延续性话题（非当日新事件，但有重要长文/认知增量输入）

## 底部标注

```markdown
_📅 数据截至 YYYY-MM-DD HH:MM CST | 💡 本简报优先服务注意力分配与后续行动，已过滤无技术细节的 PR 融资、转载洗稿与不可验证信息。_
```

若生成周报，标题使用 `# AI 情报周报 — YYYY-Www`，并将“今日结论”改为“本周结论”，“我的行动清单”改为“下周行动清单”。
